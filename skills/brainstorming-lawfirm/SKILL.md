# brainstorming-lawfirm — IRAC + 레드팀 사건 전략 메모

> Codex 에서는 셸에 `${CLAUDE_PLUGIN_ROOT}` 가 없다 — 이 문서를 연 경로에서 `.codex-plugin` 폴더가 있는 상위 폴더(플러그인 루트)를 찾아 그 절대경로로 바꿔 쓴다. Claude Code 에서는 그대로 둔다.

변호사의 사건 검토를 돕는 **내부 메모**를 만든다. 의뢰인·법원 제출용이 아니다. 비변호사의 유상 법률사무는 변호사법 제109조가 금지하므로 이 메모는 변호사의 검토 자료로만 쓰고, 결론은 변호사가 정한다.

`$B` = `${CLAUDE_PLUGIN_ROOT}/skills/brainstorming-lawfirm/scripts` · 계산기 `$C` = `${CLAUDE_PLUGIN_ROOT}/skills/litigation-calc/scripts` · 법령 `LAW` = `python3 ${CLAUDE_PLUGIN_ROOT}/skills/intent-brief/scripts/lawapi.py`

## 원칙

- 사실은 자료(사건메모·상대방 서면·계약서·증거)에서만 가져오고 출처를 붙인다. 자료에 없는 사실은 `[확인 필요: 무엇]`.
- 조문·판례는 실제로 조회한 것만 쓴다. 조문은 `LAW law <법령명> --article <조>`, 판례는 case-search 스킬(법제처·빅케이스)로 확인한다. 조회하지 못했거나 원문과 맞지 않으면 `[확인 필요: 법제처 미확인]`. 판례를 기억으로 지어내지 않는다. `LAW key status` 가 `configured: false` 면 `references/law-lookup.md` 「준비」대로 입력 창으로 키를 받고, 받지 못하면 조문·판례를 `[확인 필요: 법제처 미확인]` 으로 두고 진행한다.
- 날짜·금액은 계산기로 낸다 — 기한 `python3 "$C/deadline.py" calc …`, 인지액·이자 `python3 "$C/costs.py" …`, 위험 점수 `python3 "$B/risk.py" …`. 모델이 직접 셈하지 않는다.
- 묻는 것은 일반 텍스트로 한 번에 하나씩. 사실은 묻지 말고 자료에서 읽는다 — 묻는 것은 의뢰인의 목표·양보선 같은 판단뿐이다.

## 1. 준비

1. 사건 폴더(또는 자료)를 받고 읽는다. 자료가 없으면 먼저 달라고 하고, 받기 전에는 분석을 쓰지 않는다. 의뢰인 지위, 상대방, 청구·혐의, 진행 단계, 다음 기한을 표로 정리한다.
2. 의뢰인의 목표를 한 문장으로 확인한다(예: 「전부 승소」가 아니라 「6개월 안에 3천만 원 이상 회수」). 자료에 없으면 한 번 묻는다.
3. 쟁점 목록(3–7개)을 뽑아 보여 주고 빠진 것이 있는지 한 번 확인받는다.

## 2. IRAC — 쟁점마다

```
### 쟁점 N. <제목>
- 쟁점(Issue): <법적 질문 한 문장 — 「~인가」>
- 규범(Rule): <조문 원문 요지·요건 목록> — 출처: <법령 제N조 / 판례 번호> (확인: 법제처 원문 · 빅케이스 · [확인 필요])
- 포섭(Application):
  | 요건 | 우리 사실(출처) | 상대 사실(출처) | 판단 |
- 결론(Conclusion): <유리·불리·불확실> — 이유 한 줄, 확신도(높음·중간·낮음)
```

규범은 요건별로 쪼개고, 포섭은 요건마다 증거를 붙인다. 입증책임이 누구에게 있는지 적는다.

## 3. 레드팀 — 상대방 대리인이 되어

IRAC 결론을 일부러 깨 본다. 쟁점마다 상대방이 낼 가장 강한 반론 1–3개를 쓴다: 사실 다툼(증거의 신빙성·공백), 법리(다른 요건 해석·반대 판례), 절차(시효·제척기간·관할·실기한 공격방어방법·입증책임 전환). 가능하면 Agent 도구로 IRAC 결론을 주지 않은 별도 에이전트에게 「상대방 대리인으로서 반론만」 쓰게 해 자기 결론에 끌리지 않게 한다.

```
| 반론 | 근거(자료·조문·판례) | 재반박 | 남는 약점 |
```

재반박이 없는 반론은 「남는 약점」으로 4의 위험 표에 넣는다.

## 4. 위험 점수표

남는 약점마다 심각도(1 경미 – 5 치명: 패소·청구 감액 폭, 형사 처벌·신병, 자격·평판)와 가능성(1 희박 – 5 거의 확실: 증거 상태·판례 경향)을 매기고 근거를 한 줄씩 쓴다. 목록을 JSON(`[{"id","title","severity","likelihood","basis"}]`)으로 작업 폴더에 써서 `python3 "$B/risk.py" table <파일>` 로 정렬된 표를 받는다. 등급별 조치는 결과의 `actions` 를 쓴다. 점수는 조회한 근거만큼만 믿을 수 있다 — 근거가 `[확인 필요]` 인 항목은 표에 그대로 표시한다.

## 5. 전략 선택지

2–3개를 비교한다(예: 전부 다툼 / 쟁점 압축 후 조정 / 반소). 각 선택지마다:
- 얻는 것 · 잃는 것 · 3의 약점 중 무엇이 커지거나 줄어드는지
- 기한: 관련 기간을 `deadline.py` 로 계산해 만료일·D-day를 적는다(불변기간이면 표시)
- 비용: 인지액·송달료·지연손해금을 `costs.py` 로 계산(단가를 모르면 회분만)
- 되돌릴 수 있는지(소 취하·청구 감축 가능 시점 등)
마지막에 추천 1개와 그 조건(「증인 A가 진술하면」 등)을 쓴다. 추천은 의견일 뿐 결정은 변호사가 한다.

## 6. 산출물

사건 폴더에 `내부_YYMMDD_<사건약칭>_브레인스토밍.md` 를 쓴다(이미 있으면 `_v2`…). 맨 위에 「내부 검토용 — 의뢰인·법원 제출 금지」. 순서: 사건 개요 → 의뢰인 목표 → 쟁점별 IRAC → 레드팀 → 위험 점수표 → 전략 선택지 → `[확인 필요]` 목록 → 조회한 법령·판례 목록(조회 결과 표시). 사건 폴더를 받지 못했으면 대화에 같은 형식으로 보여 준다.

끝에 한 줄: 「AI는 실수할 수 있습니다. 법령·판례 원문과 결론은 변호사님이 확인하십시오.」
