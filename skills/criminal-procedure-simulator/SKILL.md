# 형사절차 시뮬레이터

사용자의 현재 상황을 파악한 뒤, **수사 → 기소 → 재판 → 판결 → 집행**의 전 과정을 인터랙티브 React 위젯으로 시각화해 안내하는 스킬이다.

이 스킬이 존재하는 이유: 형사절차를 처음 겪는 사람은 "앞으로 어떻게 되는 건지"가 가장 큰 불안 요소다. 전체 로드맵을 한눈에 보여주고 "지금 내가 여기 있고, 다음은 이렇다"를 명확히 안내하면 그 불안을 크게 줄일 수 있다.

> **법령 기준일**: 2025년 9월 시행 법령
> 적용 법령: 형사소송법, 검찰청법, 검사와 사법경찰관의 상호협력과 일반적 수사준칙에 관한 규정(수사준칙)

## 판례·법령 조회 (필수 선행 단계)

이 스킬은 사용자의 혐의·상황에 맞는 실제 판례와 최신 법령 조문을 확인해서 답변에 반영해야 한다. 판례 없이 일반론만 제시하면 사용자에게 실질적 도움이 크게 줄어든다. 그래서 **응답을 시작하기 전에 법제처 Open API 조회가 되는지 반드시 확인**한다.

> **법령·판례 조회** — MCP 를 쓰지 않고 법제처 Open API 를 직접 부른다(intent-brief 의 `lawapi.py`). 키(OC) 등록·스크립트 위치·명령 전체는 `../../references/law-lookup.md` 를 먼저 읽는다. 빅케이스에 로그인돼 있으면(같은 플러그인의 `case-search` 스킬, `/lawfirm:case-search-setup`) 판례 검색에 함께 쓴다.

쓰는 명령:
- `lawapi.py law <법령명> --article <조>` — 법령 확인·조문 본문(예: `law "형사소송법" --article 245-7`)
- `lawapi.py prec-search "<키워드>" --fulltext [--court 대법원]` → `lawapi.py prec <판례일련번호>` — 판례 검색·상세(판시사항, 판결요지, 참조조문)
- `lawapi.py search detc "<검색어>"` → `lawapi.py detail detc <ID>` — 헌법재판소 결정
- `casesearch.py search "<검색어>"` — 빅케이스 판례 검색(`casesearch.py status` 가 `available: true` 일 때만)

### 시나리오 A: 조회가 되는 경우 → 적극 활용

**기본 동작 (항상 수행 — 법령 조회로 연결 확인):**
1. `lawapi.py law "형사소송법"` 으로 관련 법령을 조회한다. 이 호출은 두 가지 역할을 한다:
   - 법제처 키·연결이 실제로 되는지 확인 (연결 검증)
   - 내장 콘텐츠의 법령명·시행일이 현행과 맞는지 확인
2. 조회 성공 시, 스킬에 내장된 법률 콘텐츠와 조회 결과를 함께 활용하여 답변 제공. 조문 번호를 인용할 때는 `--article` 로 본문을 한 번 확인한다

참고: 실제 답변의 법률 내용은 대부분 이 스킬에 내장된 "단계별 법률 콘텐츠"를 기반으로 한다. 법제처 조회는 내장 콘텐츠의 정확성을 보조하는 역할이다.

**판례 검색 (사용자 요청 시에만):**
아래 경우에만 판례·헌재 결정을 조회한다:
- 사용자가 "판례 찾아줘", "비슷한 사건 판례", "판례 있어?" 등 **명시적으로 판례를 요청**한 경우
- 사용자가 특정 쟁점에 대해 **법원 판단이 궁금하다**고 한 경우

판례 검색 절차:
1. 사용자의 혐의/쟁점으로 `lawapi.py prec-search "<키워드>" --fulltext` (예: "사기죄 집행유예", "폭행 불송치")
2. 검색 결과 중 가장 관련성 높은 판례 1~3건을 `lawapi.py prec <판례일련번호>` 로 상세 조회
3. 헌재 결정이 관련되면 `lawapi.py search detc` + `lawapi.py detail detc` 활용
4. 법제처에 원문이 없거나 결과가 적으면, 빅케이스가 있을 때 `casesearch.py search` 를 한 번 더 — 빅케이스에서만 찾은 판례는 「빅케이스 확인」이라고 밝힌다

**호출 실패 처리:**
- `error: outage` → 같은 명령을 1회 재시도. 그래도 실패하면 법제처 장애로 보고 내장 콘텐츠만으로 안내하되 「법제처 조회 장애 — 조문·판례 미확인」을 답변 첫머리에 밝힌다
- `error: format_changed` → 장애와 같이 처리한다

**답변에 반영하는 방식:**
- 법령 조문 번호를 항상 병기 (예: 형소법 §245의7)
- 판례를 검색한 경우에만, 관련 판례 번호와 판시사항 요지를 자연스럽게 인용

### 시나리오 B: 키가 없거나 키 오류 → 키 등록 안내

`lawapi.py key status` 가 `configured: false` 이거나 조회가 `no_key`·`key_invalid` 를 내면, 절차 안내 전에 키를 받는다.

> ⚠️ **법제처 Open API 키가 필요합니다**
>
> 정확한 형사절차 안내를 위해서는 실제 판례와 최신 법령 조문을 실시간으로 확인해야 합니다. https://open.law.go.kr 에서 회원가입 → OPEN API 사용 신청(법령·판례) 후 받은 OC 값을 곧 뜨는 입력 창에 넣어 주시면 이 PC 에 저장해 두고 바로 확인하겠습니다. (신청 때 이 PC 의 IP 주소 등록을 요구할 수 있습니다.)

키는 `../../references/law-lookup.md` 의 「준비」 절차(`lawapi.py key set --prompt` — 입력 창)로 받아 저장한다. 채팅으로 달라고 하지 않는다. **키가 없는 동안에는 절차 안내를 진행하지 않는다.** 판례와 법령을 실시간으로 확인하지 못하면 부정확한 정보를 제공할 위험이 있기 때문이다.

## 워크플로우 — "간결 응답 우선, 시각화는 요청 시에만"

형사절차를 처음 겪는 사람은 불안하고 급하다. 긴 설명보다 **질문에 대한 정확한 답 + 지금 해야 할 것**을 먼저 주는 것이 훨씬 도움이 된다. 전체 절차 시각화는 사용자가 원할 때만 제공한다.

### 0단계 — 법제처 조회 확인 (모든 응답 전 자동 수행, 게이트키퍼)

형사절차 관련 질문을 받으면, 답변을 작성하기 전에 위 "판례·법령 조회" 섹션의 절차를 수행한다. 키가 있고 조회가 되면 **법령 조회만** 수행한 뒤 1단계로 진행한다(판례 검색은 사용자 요청 시에만). **키가 없으면 키 등록 안내만 제공하고 절차 안내는 진행하지 않는다.** 이 단계는 게이트키퍼 역할을 한다.

### 1단계 — 간결 응답 (기본 모드)

사용자가 형사절차 관련 질문을 하면 **바로 핵심 답변**을 제공한다.

**응답 원칙:**
- 질문에 대한 직접적인 답변을 2~4문장으로 간결하게
- 관련 법령 조문 번호 병기 (예: 형소법 §245의7)
- 개정된 내용이면 [개정] 표시와 시행일 명시
- 사용자가 판례를 요청하면, 판례를 검색하여 판례 번호·요지를 함께 인용
- "지금 해야 할 것" 1~3가지를 우선순위로 안내
- 긴급 기한이 있으면 빨간 강조

**응답 끝에 항상 후속 질문 유도:**
답변 말미에 사용자가 다음으로 궁금해할 만한 것을 자연스럽게 물어본다. 예시:
- "다음 단계가 어떻게 진행되는지 궁금하시면 말씀해 주세요."
- "전체 절차를 한눈에 보고 싶으시면 시각화해 드릴 수 있습니다."
- "이의신청 방법이 궁금하시면 알려드릴게요."

후속 질문은 상황에 맞게 자연스럽게 구성하되, **전체 절차 시각화 제안을 항상 선택지 중 하나로 포함**한다.

**부족한 정보가 있을 때:**
답변에 꼭 필요한 정보만 **1회 최대 2개** 질문으로 간결하게 물어본다. 대화에서 이미 드러난 정보는 다시 묻지 않는다.

### 구성안 → 승인 → 작성

본문을 쓰기 전에 구성안을 보여 주고 승인을 받는다(공통 절차 `../../references/outline-approval.md`). 구성안은 일반 텍스트 한 번으로, 다섯 요소:
- 목표: 이 시뮬레이션으로 얻으려는 것 한 문장
- 쟁점 3–6개: 쟁점마다 뒷받침 증거(자료 이름·번호)를 붙인다
- 목차: 사용자 관점(피의자·피해자·참고인) · 지금 단계 · 이후 단계 순서 · 단계별 기한·선택지 · 위젯 구성(요청한 경우). 쟁점은 절차상 쟁점(구속 여부·합의·증거 다툼 등)
- 확인 필요: 자료에 없어 `[확인 필요: …]` 로 둘 사실
- 인용 예정: 쓸 조문·판례(조회 전이면 「조회 예정」)

「승인」·「진행」이면 그대로 작성하고, 고칠 점을 말하면 구성안만 고쳐 다시 보여 준다. 변호사가 「바로 작성」이라고 하면 건너뛴다.

### 2단계 — 인터랙티브 위젯 생성 (요청 시에만)

사용자가 **전체 절차 시각화를 요청**하거나, "앞으로 어떻게 되나", "전체 흐름", "절차 보여줘" 등 전체 로드맵을 원하는 경우에만 **.jsx 파일**로 인터랙티브 절차 시뮬레이터를 생성한다.

위젯 생성 전에 상황 파악이 필요하면 아래를 확인한다:

| 항목 | 예시 |
|------|------|
| **당사자 지위** | 피의자 / 피고인 / 피해자(고소인) / 고발인 / 참고인 |
| **현재 단계** | 수사 전 / 경찰 수사 중 / 경찰 수사종결 / 검찰 / 기소됨 / 공판 중 / 선고 후 |
| **구속 여부** | 구속 / 불구속 / 모름 |
| **죄명(혐의)** | 사기, 폭행, 음주운전, 횡령 등 |
| **특이사항** | 친고죄, 초범, 합의 여부, 약식명령, 정식재판 청구 등 |

정보가 모호하더라도 합리적 추정 하에 시작하되, 추정한 부분은 명시한다.

#### 위젯 필수 구성요소

1. **절차 타임라인 (메인 뷰)**
   - 세로형 스텝퍼(stepper) 레이아웃
   - 각 단계를 노드로 표시하고, 분기점은 갈래길로 시각화
   - 현재 단계: 노란색(amber) 배경 + 📍 아이콘
   - 완료 단계: 초록색 + ✅
   - 미래 단계: 회색 아웃라인
   - 단계 간 연결선으로 흐름 표시

2. **단계 상세 패널 (클릭/탭 시 펼침)**
   - 해당 단계에서 해야 할 것 (액션 아이템)
   - 당사자의 권리
   - 주의사항 및 기한
   - 예상 소요 기간
   - 가능한 분기/결과

3. **분기 안내**
   - 경찰 수사종결 후: 송치 vs 불송치
   - 검찰 처분: 기소 vs 불기소 vs 약식기소
   - 약식명령 후: 수용 vs 정식재판 청구
   - 1심 후: 수용 vs 항소
   - 각 분기마다 결과가 어떻게 달라지는지 표시

4. **긴급 기한 배너**
   - 7일 (항소, 정식재판 청구), 30일 (항고), 90일 (검사 재수사 검토) 등
   - 빨간색 배너로 눈에 띄게 표시

5. **[개정] 배지**
   - 최근 개정된 내용에 파란색 [개정] 뱃지 표시
   - 호버/클릭 시 개정일과 변경 내용 표시

#### 디자인 원칙

- Tailwind CSS 유틸리티 클래스만 사용
- lucide-react 아이콘 활용 가능
- 모바일에서도 잘 보이도록 반응형
- 색상 체계: amber(현재 단계), green(완료), red(긴급 기한), blue(개정 배지), gray(미래 단계)
- 다크/라이트 모두 고려한 대비 확보
- 한글 폰트 가독성 최우선

### 3단계 — 단계별 법률 콘텐츠

아래는 위젯의 각 단계에 들어갈 핵심 콘텐츠다. 사용자의 지위(피의자/피해자)에 따라 관련 내용만 선별해 위젯에 반영한다.

---

#### A. 피의자·피고인 관점

**[A-1] 수사 개시 (고소·신고·인지)**
- 체포 시 고지 의무: 피의사실 요지, 변호인 선임권, 진술거부권 (형소법 §200의5)
- 임의동행: 거부 가능, 실질적 체포 시 영장 필요
- 긴체포(긴급체포): 48시간 내 구속영장 청구 또는 석방 (형소법 §200의4)
- 권리: 진술거부권(§244의3), 변호인 조력권(§243의2)

**[A-2] 경찰 수사** ← 2021년 이후 가장 핵심적 단계
- 경찰이 1차 수사권자이자 수사종결권자 — 대부분 사건이 경찰에서 종결됨
- 불송치결정을 이끌어내면 즉시 피의자 신분 해소, 전과 기록 없음
- 변호인 선임·조사 동석 요청 (§243의2)
- [개정] 심야조사 제한: 21시~06시 원칙 금지 (수사준칙 §21)
- [개정] 별건수사 금지: 합리적 근거 없이 다른 범죄 수사 불가 (형소법 §198④)
- 장시간 조사 제한: 1일 8시간 원칙 (수사준칙 §22)
- 구속기간: 경찰 10일 + 연장 10일 (§202)
- **구속적부심**: 구속의 적법성을 법원에 심사 청구 (§214의2) — 구속 직후 즉시 가능
- 예상 기간: 1~6개월

**[A-3] 경찰 수사종결** ← 2021년 신설
- 처리 유형 (§245의5):
  - **기소의견 송치**: 혐의 있음 → 검찰 이송
  - **불기소의견 송치**: 혐의 있으나 기소 불필요 → 검사 최종 판단
  - **불송치결정**: 경찰 자체 종결 → 피의자 신분 해소
- 불송치 후 흐름:
  - 경찰 7일 이내 고소인·피해자 서면 통지 (§245의6)
  - 검사 90일 내 기록 검토, 재수사 요청 1회 가능 (§245의8)
  - 피해자·고소인 이의신청 → 즉시 검찰 송치 (§245의7)
  - ⚠️ 고발인은 이의신청권 없음 (2022. 9. 10.)

**[A-4] 검찰 수사 및 처분**
- 검사 직접수사 가능 범죄: 부패범죄·경제범죄만 (검찰청법 §4①1가)
- 일반 범죄는 보완수사 요구만 가능 (§197의2) — 수사지휘 아님
- [개정] 검사 작성 피의자신문조서: 피고인 법정에서 내용 인정해야만 증거 (§312①)
- 처분 종류:

| 처분 | 결과 |
|------|------|
| 기소(공소제기) | 공판 개시 |
| 약식기소 | 벌금형 → 7일 내 정식재판 청구 가능 (§453) |
| 불기소(혐의없음/죄가안됨/공소권없음) | 전과 없음, 종결 |
| 기소유예 | 전과 없음, 재기수사 가능성 |

- 예상 기간: 1~3개월

**[A-5] 공판 (형사재판)**
- 공판 순서: 공소장 부본 송달(§266) → 공판준비기일(필요 시, §266의5) → 공판기일(모두진술·증거조사·피고인 신문·최종변론) → 선고
- [개정] 공판중심주의 강화: 검사·경찰 작성 조서 모두 피고인 내용 인정 없으면 증거 불가 (§312①③)
- [개정] 피해자 소송기록 열람·등사 원칙 허용 (§294의4)
- 피고인 핵심 권리: 진술거부권(§283의2), 최후진술권(§303), 증거 열람·등사(§266의3), 국선변호인(§33)
- **보석**: 구속 피고인이 보증금 납부 조건으로 석방 신청 (§94~§100)
- 예상 기간: 1심 3~12개월

**[A-6] 선고 및 상소**
- 항소 기한: 선고일로부터 **7일 이내** (§358) — 절대 엄수
- 항소심: 고등법원 / 상고심: 대법원(법률심, §383)
- 집행유예 주의: 유예 기간 중 재범 시 실형 전환
- [2027 시행 예정] 하급심 판결문 열람 가능

**[A-7] 형 집행 및 전과**
- 실형: 교정시설 수감 / 벌금: 미납 시 노역장 유치
- 전과 기록: 형확정 시 수사경력자료에 기록
- 사면·복권, 형집행정지 등 특수 절차 안내
- 재심 청구 요건 (§420)

---

#### B. 피해자·고소인 관점

**[B-1] 고소장 제출**
- 일반 범죄: 경찰서 제출 / 부패·경제 범죄: 검찰 접수 가능
- 친고죄: 고소 취소 후 재고소 불가 (§232), 고소기간 6개월 확인 (§230)
- 공소시효 확인 필수 (§249)
- 고발인은 불송치 이의신청권 없음 (2022. 9. 10.)

**[B-2] 경찰 수사 협조 및 불송치 대응**
- 불송치 통지 수령 후 이의신청 가능 (§245의7)
- 이의신청 시 경찰이 즉시 검찰 송치
- 미신청해도 검사 90일 내 재수사 요청 가능 (1회)
- 실태: 불송치 사건 91%가 검찰 개입 없이 종결 → 적극 이의신청 권고

**[B-3] 검찰 처분 및 불복**
- 불기소 불복 3단계:
  1. **항고**: 고등검찰청, 30일 이내 (§260)
  2. **재항고**: 검찰총장 (§260의2)
  3. **재정신청**: 고등법원 — 인용 시 공소제기 강제 (§260 이하)

**[B-4] 공판 참여**
- 피해자 진술 신청 (§294의2)
- [개정] 소송기록 열람·등사 원칙 허용 (§294의4)
- 배상명령 신청 (소촉법 §25, 일부 죄종)
- 공판기일 통지 요청 (§294의2④)

**[B-5] 판결 및 피해 회복**
- 배상명령 이행 확인 → 미이행 시 강제집행
- 민사 손해배상 소송 별도 검토 (소멸시효 확인)
- 범죄피해자구조금 신청 (범죄피해자보호법)

---

#### C. 참고인 관점

**출석 및 진술**
- 출석 의무: 정당한 사유 없이 불출석 시 과태료·동행영장 가능
- 진술거부권: 자기 또는 친족의 형사책임에 관한 사항은 거부 가능 (§148, §149)
- 참고인에서 피의자로 전환되는 경우: 즉시 진술거부권·변호인 선임권 고지받아야 함
- 증인 보호: 신변안전조치 신청 가능 (범죄피해자보호법)

---

#### D. 특수 절차

**즉결심판**
- 20만원 이하 벌금·구류·과료 대상 경미 범죄 (즉결심판에 관한 절차법)
- 경찰이 즉결심판 청구 → 약식재판보다 빠름
- 정식재판 청구 가능 (7일 이내)

**약식명령 → 정식재판 전환**
- 약식명령 고지 후 7일 이내 정식재판 청구 (§453)
- 정식재판 청구 시 불이익변경금지 원칙 없음 — 더 무거운 형 선고 가능 주의
- 피고인뿐 아니라 검사도 정식재판 청구 가능

**구속적부심**
- 구속 후 즉시 청구 가능 (§214의2)
- 법원이 48시간 내 심문·결정
- 인용 시 즉시 석방

**보석**
- 보증금 조건부 석방 (§94~§100)
- 필요적 보석(§95): 일정 요건 충족 시 법원이 원칙적 허가
- 임의적 보석(§96): 법원 재량
- 보석 취소 사유: 도주, 증거 인멸, 출석 불응 등

### 3단계 — 위젯 생성 후 보충 (위젯 생성 시에만)

위젯을 생성한 경우, 대화에서 다음을 간결하게 보충한다:

1. **현재 단계 요약**: 사용자의 상황을 1~2문장으로 정리
2. **즉시 행동 항목**: "지금 당장 해야 할 것" 1~3가지
3. **기한 경고**: 임박한 기한이 있으면 명확히 경고
4. **후속 질문 유도**: "더 궁금한 부분이 있으시면 말씀해 주세요"

## 유의사항·상담 안내 — `../../references/cta-config.md`

형사절차 시뮬레이터 결과물(채팅 응답의 면책 고지 아래, .jsx 위젯의 절차 타임라인·면책 고지 아래) 끝에 유의사항을 붙인다. 문장·템플릿은 **`../../references/cta-config.md`** 를 읽어 그대로 쓴다.
- 유의사항 문장은 그 파일의 1문장만 쓴다. 생략하지 않는다.
- 상담 안내는 사용 변호사의 사무소 정보 파일(macOS `~/.intent-brief/office.json`, Windows `%LOCALAPPDATA%\intent-brief\office.json`)이 있을 때만 붙인다. 없으면 붙이지 않는다 — 다른 사무소 정보로 채우거나 지어내지 않는다.

**위젯 안내 디자인 지침:**
- 타임라인/절차 콘텐츠와 안내 사이에 구분선 삽입
- 안내 영역 배경: 연한 회색(gray-50) 또는 연한 파란색(blue-50)
- 사무소 이름 줄은 굵게, 본문보다 한 단계 큰 폰트
- "[유의사항]"·"[상담 안내]" 제목은 굵게, 가운데 정렬
- 전체 안내 영역은 가운데 정렬, 둥근 모서리(rounded-lg), 적절한 패딩
- 사무소 정보가 있으면 전화·이메일은 클릭 가능한 링크로 처리 (tel:, mailto:)

유의사항은 생략하지 않는다. 형사절차 시뮬레이터를 생성할 때마다 채팅 응답과 .jsx 위젯 양쪽 모두에 넣는다.
