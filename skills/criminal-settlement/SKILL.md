# 형사 합의서 작성 스킬

## 개요

사용자와 대화를 통해 필수 정보를 수집하고, 전문적인 형식의 형사 합의서 .docx 파일을 생성한다.
**사건 유형 제한 없음** — 형사 사건이라면 무엇이든 처리한다.

---

## Step 1: 맥락 파악 후 정보 수집

### 1-A. 이미 제공된 정보 먼저 확인

사용자가 대화 중 이미 언급한 정보(사건 유형, 당사자 이름, 합의금 등)는 다시 묻지 않는다.
대화 내역에서 추출할 수 있는 정보를 최대한 채우고, **빠진 항목만** 질문한다.

### 1-B. 부족한 정보 한 번에 질문

빠진 정보를 항목별로 나누어 여러 번 묻지 말고, **한 메시지에 묶어서** 질문한다.

**수집해야 할 전체 항목 목록:**

```
[사건]
- 사건 유형 (어떤 범죄인지 — 모르면 '기타'로 처리)
- 고소 사건번호 (경찰서명 포함, 없으면 생략)

[피해자 (갑)]
- 성명
- 생년월일 (0000. 00. 00.)
- 주소

[가해자 (을)]
- 성명
- 생년월일
- 주소

[합의 조건]
- 합의금액
- 지급 방법: 일시불 / 분할지급
  → 일시불 시: 지급 기한
  → 분할지급 시: 각 회차별 금액과 지급기한 (예: 1회 500만원 4/30, 2회 500만원 5/30)
- 입금 방식 (계좌이체 / 현금)
  → 계좌이체 시: 은행명, 계좌번호, 예금주
- 특별히 포함할 조항 (없으면 사건 유형 기본값 적용)
- 합의서 작성일
```

**모르는 항목은 ○○○ / ○○으로 처리하고 계속 진행한다. 완벽한 정보를 기다리지 않는다.**

---

## 구성안 → 승인 → 작성

본문을 쓰기 전에 구성안을 보여 주고 승인을 받는다(공통 절차 `../../references/outline-approval.md`). 구성안은 일반 텍스트 한 번으로, 다섯 요소:
- 목표: 이 합의서로 얻으려는 것 한 문장
- 쟁점 3–6개: 쟁점마다 뒷받침 증거(자료 이름·번호)를 붙인다
- 목차: 당사자 · 사건 표시 · 합의금 · 지급 방법(일시·분할) · 처벌불원 의사 · 특약 · 서명
- 확인 필요: 자료에 없어 `[확인 필요: …]` 로 둘 사실
- 인용 예정: 쓸 조문·판례(조회 전이면 「조회 예정」)

「승인」·「진행」이면 그대로 작성하고, 고칠 점을 말하면 구성안만 고쳐 다시 보여 준다. 변호사가 「바로 작성」이라고 하면 건너뛴다.

## Step 2: 합의서 생성

수집한 정보를 바탕으로 `scripts/generate.js`를 실행하여 .docx 파일을 생성한다.

실행 전에 `generate.js` 가 있는 `scripts/` 폴더에서 `node -e "require('docx')"` 를 실행한다. 실패하면 「문서 생성에 Node.js 와 docx 모듈이 필요합니다 — 터미널에서 `npm install --prefix ~ docx` 를 실행한 뒤 다시 요청해 주십시오(Node.js 가 없으면 nodejs.org 에서 먼저 설치)」 한 줄을 보이고 멈춘다(전역 설치 `-g` 만으로는 `require` 해석 경로에 없다).

### 실행 방법

**Claude Code 플러그인**: 스크립트는 이 스킬 폴더의 `scripts/generate.js` 다(스킬을 불러올 때 표시되는 「Base directory for this skill」 경로 아래). `--output` 은 아래 「저장 위치 확인 절차」로 정한 경로를 준다.

JSON 데이터는 **셸 명령에 직접 넣지 않는다** — 당사자 이름·사건 내용에 따옴표(`'`)가 들어 있으면 명령이 깨지거나 다른 명령이 실행될 수 있다. 먼저 Write 도구로 JSON 을 파일(예: 저장 위치의 `합의서_데이터.json`)에 쓰고 그 경로를 넘긴다. 경로는 큰따옴표로 감싼다.

```bash
node "<스킬 폴더>/scripts/generate.js" --data "<JSON 파일 경로>" --output "<저장 위치>/형사합의서_피해자성명_사건유형.docx"
```

생성이 끝나면 JSON 파일은 지운다(개인정보).

### 파일 저장

파일을 저장하기 전에 **반드시 사용자에게 저장 위치를 확인**해야 한다. 사용자가 원하는 폴더에 파일을 저장하는 것이 핵심이다. 묻지 않고 기본 경로에 바로 저장하지 않는다.

#### 저장 위치 확인 절차

1. .docx 파일 생성이 완료되면, 파일을 저장하기 **전에** 사용자에게 저장 위치를 질문한다:
   - "합의서가 준비되었습니다. 어느 폴더에 저장할까요?" 와 같이 자연스럽게 묻는다
   - 일반 텍스트로 선택지를 번호와 함께 제시한다. 선택지 예시:
     - "기본 출력 폴더" (현재 작업 폴더)
     - "바탕화면"
     - "다른 경로 직접 입력" (사용자가 원하는 경로를 자유롭게 지정)

2. 사용자가 특정 경로를 지정하면:
   - 해당 경로가 존재하는지 확인한다 (없으면 생성할지 물어본다)
   - 쓰기 권한이 있는지 확인한다
   - 권한이 확보되면 해당 경로에 파일을 저장한다

3. 사용자가 "기본 폴더", "아무 데나", "상관없어" 등으로 답하면:
   - 사용자의 현재 작업 폴더(cwd)에 저장한다

파일명은 `[날짜]_형사합의서_[피해자성명]_[사건유형].docx` 형식으로 한다 (예: `20260320_형사합의서_김철수_상해.docx`). 날짜는 YYYYMMDD 형식이다.

**중요:** 임시 디렉토리(`/tmp/` 등)에만 파일을 남기면 사용자가 접근할 수 없다. 사용자가 지정한 경로 또는 기본 출력 폴더에 직접 생성하거나 복사해야 한다. 저장 후 파일의 절대 경로를 사용자에게 알려 준다.

---

## Step 3: 출력 및 안내

1. 위 "파일 저장" 섹션의 절차에 따라 사용자에게 저장 위치를 묻고, 지정된 폴더에 .docx 파일을 저장한다
2. 저장한 파일의 절대 경로 안내
3. 다음 사항을 사용자에게 안내:
   - ○○○ 처리된 부분 확인 및 수정 필요
   - 서명·날인란은 직접 서명 (자필 서명 또는 인감/막도장 날인)
   - 법률 전문가 검토 권장
   - 합의금 수령 전 고소 취하 금지 (합의금 수령과 동시에 처리 권장)

## 특약 조항 가이드

### 항상 기본 포함 (모든 사건)
- **고소 취하**: 합의금 수령과 동시에 고소 취하
- **처벌불원**: 을의 처벌을 원하지 않음 확약
- **추가 청구 포기**: 동일 사건 민·형사 이의 포기

### 사건 성격에 따라 판단하여 추가
| 조항 | 적합한 상황 |
|------|------------|
| 접근금지 | 당사자 간 물리적 충돌이 있었던 경우 |
| 게시물 삭제 | 온라인·SNS 게시물이 관련된 경우 |
| 공개 사과 | 명예·신용 훼손이 있었던 경우 |
| 추가 게시 금지 | 온라인 명예훼손 시 재발 방지 |
| 위약금 | 이행 확보가 특히 중요한 경우 |
| 기한이익 상실 | 분할지급 시 자동 추가 — 1회라도 불이행 시 잔액 전부 즉시 청구 |
| 합의금 미지급 시 효력 상실 | 분할 지급이거나 신뢰 우려가 있는 경우 |
| 기타 | 사용자가 별도 요청한 내용 |

사용자가 특약을 별도로 지정하지 않은 경우, 사건 내용을 바탕으로 Claude가 적합한 조항을 판단하여 제안하고 확인받는다.

## 품질 기준

- 피해자=갑, 가해자=을 표기 일관성 유지
- 합의금은 숫자(₩ 표기) + 한글 병기
- 날짜는 "0000. 00. 00." 형식 통일
- 고소 사건번호 명시 (경찰서명 포함)
- 서명란에 성명, 생년월일, 주소, (인) 포함
- 조항 번호는 ① ② ③ 순서대로 동적 부여 — 사용하지 않는 특약이 있어도 번호가 점프하지 않는다

## 유의사항·상담 안내 — `../../references/cta-config.md`

모든 형사 합의서 결과물 끝에 유의사항을 붙인다(채팅 응답의 안내사항 다음, .docx 문서 맨 마지막 별도 페이지 — `generate.js` 가 `cta-config.md` 의 문장과 사무소 정보 파일을 읽어 넣는다). 문장·템플릿·서식은 **`../../references/cta-config.md`** 를 읽어 그대로 쓴다.
- 유의사항 문장은 그 파일의 1문장만 쓴다. 생략하지 않는다.
- 상담 안내는 사용 변호사의 사무소 정보 파일(macOS `~/.intent-brief/office.json`, Windows `%LOCALAPPDATA%\intent-brief\office.json`)이 있을 때만 붙인다. 없으면 붙이지 않는다 — 다른 사무소 정보로 채우거나 지어내지 않는다.
- 문서유형: "형사 합의서" · 제출 안내: "법원 제출 시 본 페이지는 제외하십시오."

유의사항은 생략하지 않는다. 합의서를 생성할 때마다 채팅 응답과 .docx 문서 양쪽 모두에 넣는다.
